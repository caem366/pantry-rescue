Pantry Rescue

Meal planning that starts with a real kitchen—and ends with a user-reviewed retailer cart.

Core journey

Pantry inventory
Rescue plan
Approve gaps
Choose retailer
Live browser agent
Cart review

Hero shopping experience

One tested retailer/marketplace path is operated by a visible browser agent. It searches only approved gaps, reads results, chooses sensible products and quantities, adds them to the real cart, and stops before checkout.

Real browser navigation

Reliable fallback

If the live site changes, blocks automation, needs unavailable authentication, or fails safely, a clearly labelled Demo Retailer runs the same approved gaps and shared decision rules. It is functional—not prerecorded.

Demo path, candidly labelled

Transparent task state

Shopping · 2/5 complete
✓ Parmesan — 200 g wedge added
✓ Vegetable stock — 900 mL carton added
● Searching for lemons…
○ Tortillas · ○ Avocados

Every ingredient resolves as Added, Needs attention, or Skipped. Browser interruption, login/anti-automation friction, unavailable products, or uncertainty never become fake success.

Unchanged guardrails

The user stays in control

No checkout, payment, delivery/pickup choice, account handling, or meaningful substitution happens automatically. The agent stops at cart review.

One supported path, not universal compatibility

Unsupported retailers are candidly unavailable. The live adapter and demo adapter both receive the same calculated missing-ingredient data.

Kitchen-first product identity

Warm kitchen mode, calm operational agent mode, use-soon → rescued visual transition, inspectable meal reasoning, and honest low-rescue/no-plan states remain unchanged.
