Live Browser Adapter

After early validation with one benign task, the selected browser-agent capability visibly controls one tested retailer site: navigate, search, read results, choose practical products/quantities, add to cart, and stop at review.

One retailer onlyNo paymentNo credentials stored

Demo Retailer Adapter

Uses the same approved gaps and matching rules against a local product catalog. It is a functional, clearly labelled completion path if login, anti-automation friction, navigation loss, product availability, or site change prevents safe live execution.

One item, two possible executors

Vegetable stock · ~750 mL → queue task → searching → evaluating → either a live browser or local catalog finds a 900 mL carton → explain “smallest suitable available size” → Added, Needs attention, or Skipped.

Implementation boundaries

  • shoppingAgent.ts: task states and shared decision rules.
  • retailerAdapters.ts: live browser vs. demo execution boundary.
  • planner.ts: curated recipe scoring and deduplicated gaps.
  • localStorage: pantry/latest plan only.

Required early proof

Before claiming the live hero path, test the actual browser-agent capability and one retailer with a harmless cart-building task. If it does not work safely and reliably, record the Demo Retailer flow and make no live-cart claim.

Failure contract

Never fake success

Login/anti-automation friction, unavailable products, lost navigation, uncertain matches, or browser-agent errors become Needs attention. Continue independent items where possible and return control to the user.

Still no checkout

The agent never selects delivery/pickup, payment, final substitutions, or purchase. The terminal state is cart review.
